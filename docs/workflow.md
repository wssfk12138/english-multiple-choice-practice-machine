# Windows 发布副本工作流

## 接收获批改动

核实源版本、获批范围和目标差异，按最小必要 diff 落地并验证，不整仓复制。仅当整个提交适合目标且有明确授权时采用按提交移植。不得将“同意同步”推导为推送或 Release；本地提交也按已有对应授权执行。

## 发布准备

检查 Git 状态、所选差异和发布资产，排除私人数据、密钥、题库、日志、临时记录和未获批改动。按风险复用有效验证；检查当前 hooksPath、pre-push 与 CI，不绕过保护或照抄历史批准环境变量。获准推送后才核验远端结果，未推送不声称线上更新。

## 发行

版本、构建、更新清单和资产步骤按 release-windows.md 与当前源码/工作流核验。同步、推送、手动触发发行及上传资产各须对应授权。既有文档是技术参考，不代表授权，也不保证旧流程仍适合当前分支。
